# คำศัพท์โดเมน

- **เงินเก็บ (Savings):** เงินที่ผู้ใช้กันออกจากยอดเงินพร้อมใช้ผ่านรายการประเภท `saving` โดยไม่ถือเป็นรายจ่าย
- **ยอดเงินพร้อมใช้ (Available Balance):** รายรับรวมลบด้วยรายจ่ายรวมและเงินเก็บรวม เป็นยอดสูงสุดที่สามารถนำไปสร้างรายการเงินเก็บใหม่ได้
- **รายการเงินเก็บ (Saving Transaction):** รายการที่เพิ่มยอดเงินเก็บและลดเงินพร้อมใช้ในจำนวนเดียวกัน
- **เป้าหมายเงินเก็บ (Savings Goal):** จำนวนเงินเป้าหมายที่ผู้ใช้กำหนดเพื่อใช้เปรียบเทียบกับยอดเงินเก็บรวม
- **ความคืบหน้าเงินเก็บ (Savings Progress):** สัดส่วนของยอดเงินเก็บรวมต่อเป้าหมายเงินเก็บ โดยแสดงร่วมกับจำนวนเงินจริงทั้งสองค่า
- **หมวดหมู่เงินเก็บ (Savings Category):** การจำแนกรายการเงินเก็บตามวัตถุประสงค์ เพื่อใช้รวมยอดและแสดงสัดส่วนในกราฟเงินเก็บ
- **รายละเอียดหมวดเงินเก็บ (Savings Category Tooltip):** แผงข้อมูลชั่วคราวที่เปิดจากส่วนสีหรือ legend ของหมวดเงินเก็บผ่าน hover, focus หรือการแตะ และแสดงตัวเลขสรุปของหมวดนั้นร่วมกับสถานะต่อเป้าหมาย
- **พื้นที่รับการโต้ตอบ (Hit Target):** พื้นที่ที่รับ pointer หรือ touch event ของส่วนควบคุม โดยในกราฟวงแหวนต้องเป็น Donut Segment และต้องไม่ถูก Presentation Overlay ตรงกลางดัก event
- **Interactive Donut Primitive:** UI primitive กลางที่เป็นเจ้าของ geometry และ interaction contract ของกราฟวงแหวน โดยไม่รู้ความหมายทางโดเมนของรายจ่ายหรือเงินเก็บ
- **Canonical Chart Interaction:** พฤติกรรมมาตรฐานชุดเดียวสำหรับการเลือกส่วนกราฟ การ pin tooltip, keyboard, touch และ dismissal ซึ่งกราฟวงแหวนทุก Feature ต้องใช้ร่วมกัน
- **Floating Tooltip:** Tooltip ที่ติดตาม pointer ด้วยพิกัด viewport พร้อม offset และ collision handling โดยจะหยุดนิ่งเมื่อถูก pin
- **Pinned Tooltip:** สถานะที่ Tooltip ล็อกทั้งข้อมูลและตำแหน่งจนกว่าจะเลือก item ใหม่ ปิดซ้ำ กด Escape หรือ interact ด้านนอก
- **รายรับเทียบรายจ่ายวันนี้ (Daily Cashflow Comparison):** การเปรียบเทียบยอดรายรับกับรายจ่ายเฉพาะวันปฏิทินท้องถิ่นปัจจุบัน โดยไม่รวมเงินเก็บ
- **สรุปกระแสเงินวันนี้ (Daily Cashflow Summary):** Derived Data ที่รวมยอด เปอร์เซ็นต์ จำนวนรายการ และรายการมูลค่าสูงสุด แยกฝั่งรายรับกับรายจ่ายของวันนี้
- **รายการมูลค่าสูงสุดร่วมกัน (Joint Highest-value Transactions):** Transaction ทุกแถวในฝั่งเดียวกันที่มียอดเท่ากับค่าสูงสุด โดยต้องแสดงครบและเรียงใหม่สุดก่อน
- **เวลาที่สร้างรายการ (Created At):** วันเวลาจริงที่ Transaction ถูกสร้างและเป็น source of truth สำหรับการจัดกลุ่มตามวันและการเรียงลำดับ
- **หน้ารายการธุรกรรม (Transaction Page):** รายการย่อยสูงสุด 10 รายการที่ได้หลังกรองและเรียง Transaction แล้ว
- **ขอบเขตวันท้องถิ่น (Local Day Boundary):** ช่วงตั้งแต่เที่ยงคืนถึงก่อนเที่ยงคืนถัดไปตาม timezone ของ browser ซึ่งใช้ตัดสินว่า Transaction อยู่ใน “วันนี้” หรือไม่

- **รายการ (Transaction):** การเคลื่อนไหวของเงินหนึ่งครั้ง
- **รายรับ (Income):** รายการที่เพิ่มยอดเงินคงเหลือ
- **รายจ่าย (Expense):** รายการที่ลดยอดเงินคงเหลือ
- **ยอดคงเหลือ (Balance):** รายรับรวมลบด้วยรายจ่ายรวม
- **งบประมาณ (Budget):** วงเงินรายจ่ายที่ตั้งไว้สำหรับเดือนปัจจุบัน
- **หมวดหมู่ (Category):** กลุ่มของรายการ เช่น อาหาร เดินทาง หรือช้อปปิ้ง
- **การลบรายการ (Delete Transaction):** การนำรายการออกจากข้อมูลของอุปกรณ์ แล้วคำนวณยอดใหม่จากรายการที่เหลือ
- **ธีม (Theme):** ชุดสีของหน้าจอ มีค่า `light` หรือ `dark`
- **ค่าธีมของผู้ใช้ (Theme Preference):** ธีมล่าสุดที่ผู้ใช้เลือกและบันทึกไว้ในเบราว์เซอร์
- **ธีมระบบ (System Theme):** ค่ารูปแบบสีจาก `prefers-color-scheme` ซึ่งใช้เมื่อยังไม่มี Theme Preference ที่ถูกต้อง
- **พื้นผิวการตั้งค่า (Settings Surface):** พื้นที่ที่เปิดหลังผู้ใช้กดตั้งค่า โดยเป็น popover บนเดสก์ท็อปและ bottom sheet บนมือถือ
- **ปุ่มเปลี่ยนธีม (Theme Toggle):** ปุ่มไอคอนที่แสดงธีมปลายทางและเปลี่ยน Theme เมื่อกด
- **คำขอลบ (Delete Request):** ความตั้งใจลบ Transaction ซึ่งยังไม่เปลี่ยน state จนกว่าจะได้รับการยืนยัน
- **การยืนยันการลบ (Delete Confirmation):** dialog ที่แสดง Transaction และจำนวนเงินเพื่อให้ผู้ใช้ยืนยันหรือออกจากขั้นตอนอย่างปลอดภัย
- **การยกเลิก (Cancel):** การกดปุ่มยกเลิกใน Delete Confirmation โดยเฉพาะ แยกจากการปิด dialog ด้วย Escape หรือพื้นที่ด้านนอก
- **การย้อนกลับ (Undo):** การคืน Transaction ที่เพิ่งลบไปยังตำแหน่งเดิมภายในเวลา 5 วินาที
- **รายการที่ถูกนำออก (Removed Transaction):** Transaction พร้อมตำแหน่งเดิมที่เก็บไว้ชั่วคราวระหว่างช่วง Undo
- **สรุปหมวดหมู่ (Category Summary):** ข้อมูลรวมของ Category ได้แก่จำนวนเงิน เปอร์เซ็นต์ จำนวน Transaction และค่าเฉลี่ย
- **ส่วนกราฟ (Donut Segment):** พื้นที่ interactive ของ Category หนึ่งหมวดในกราฟวงแหวน
- **การลดการเคลื่อนไหว (Reduced Motion):** รูปแบบ interaction ที่รักษาข้อมูลและ feedback แต่ตัดการยก เลื่อน หมุน หรือขยายตามค่าระบบของผู้ใช้
- **Feature:** ขอบเขตความสามารถของผลิตภัณฑ์ที่เป็นเจ้าของ UI, state orchestration, domain logic, types และ styles ที่เกี่ยวข้อง
- **Feature-based Architecture:** การจัดโครงสร้างโค้ดตามความสามารถของผลิตภัณฑ์ แทนการรวมไฟล์ทุกชนิดไว้ในโฟลเดอร์กลาง
- **Behavior-preserving Refactor:** การเปลี่ยนโครงสร้างภายในโดยไม่เปลี่ยนผลลัพธ์หรือ interaction ที่ผู้ใช้สังเกตได้
- **Characterization Test:** การทดสอบที่บันทึกพฤติกรรมปัจจุบันเพื่อป้องกัน refactor เปลี่ยน behavior โดยไม่ตั้งใจ
- **Presentational Component:** component ที่รับข้อมูลและ callbacks ผ่าน props และไม่จัดการ persistence หรือ business workflow
- **Feature Hook:** hook ที่ประสาน state, lifecycle และ side effects ภายในขอบเขต Feature
- **Domain Function:** pure function ที่ทำงานกับแนวคิดทางธุรกิจโดยไม่พึ่ง React, DOM หรือ browser API
- **Storage Adapter:** ขอบเขตที่รับผิดชอบ storage keys, serialization, validation, versioning และ fallback โดยซ่อนรายละเอียดจาก UI
- **Derived Data:** ข้อมูลที่คำนวณจาก source of truth เช่น Balance หรือ Category Summary ซึ่งไม่ควรถูกเก็บซ้ำใน state
- **Public Interface:** types, components หรือ functions ที่ Feature อนุญาตให้ส่วนอื่น import โดยไม่เข้าถึงรายละเอียดภายใน
- **UI Primitive:** component พื้นฐานที่มีการใช้ซ้ำจริงข้าม Feature เช่น Button, Modal, Card หรือ Toast
- **Design Token:** ตัวแปร CSS ที่ตั้งชื่อตามความหมายของการออกแบบและใช้เป็นแหล่งค่ากลาง เช่นสี surface, Expense หรือ focus ring
- **Semantic Token:** Design Token ที่บอกบทบาทของค่าแทนชื่อสีหรือตำแหน่ง เช่น `--color-expense`
- **Style Ownership:** ขอบเขตว่า Feature หรือ component ใดรับผิดชอบ selectors, responsive rules และ animations ชุดหนึ่ง
- **CSS Module:** stylesheet ที่ scope class names อยู่ภายใน module เพื่อลดการชนกันและการพึ่งพาข้าม component
- **Global Foundation:** CSS ระดับแอปที่จำกัดเฉพาะ reset, typography, Theme application และ accessibility policy
- **Overlay Primitive:** UI foundation ที่ใช้ซ้ำสำหรับ backdrop และ surface โดยไม่เป็นเจ้าของเนื้อหาหรือ workflow ของ Feature
- **Visual Matrix:** ชุด combination ของ viewport, Theme และ Motion ที่ต้องตรวจเพื่อป้องกัน visual regression
- **Legacy Selector:** global selector จากโครงสร้างเดิมที่รอการย้ายไปยัง owner ที่ถูกต้องและต้องลบเมื่อไม่มี consumer
- **ผู้ใช้ (User):** บุคคลภายในระบบซึ่งอาจเป็นเจ้าของกระเป๋าหรือผู้รับแชร์
- **บัญชียืนยันตัวตน (Auth Account):** ตัวเชื่อม User กับบัญชีจากผู้ให้บริการเข้าสู่ระบบ เช่น Google โดยอ้างอิงตัวระบุถาวรของผู้ให้บริการ
- **กระเป๋า (Wallet):** ขอบเขตข้อมูลทางการเงินที่รวม Transaction และ Savings Goal และมี Owner หนึ่งคน
- **กระเป๋าส่วนตัว (Personal Wallet):** Wallet หลักที่ระบบสร้างให้ User หลังเริ่มใช้งาน โดย UI รุ่นแรกให้ User จัดการกระเป๋าหลักของตนหนึ่งใบ
- **สมาชิกกระเป๋า (Wallet Membership):** ความสัมพันธ์ที่กำหนดว่า User เป็น `owner` หรือ `viewer` ของ Wallet
- **เวลาเปิดดูล่าสุด (Last Viewed At):** เวลาล่าสุดโดยประมาณที่ Viewer เปิด Wallet ซึ่งแสดงแก่ Owner โดยไม่เก็บประวัติการดูรายหน้าหรือราย Transaction
- **การออกจากกระเป๋าที่แชร์ (Leave Shared Wallet):** การที่ Viewer ยืนยันเพื่อยุติ Membership ของตน โดยไม่เปลี่ยนแปลง Wallet หรือข้อมูลของ Owner
- **คำเชิญเข้ากระเป๋า (Wallet Invitation):** คำเชิญอายุ 7 วันแบบใช้ครั้งเดียวที่ Owner ส่งไปยัง email ที่กำหนด ผู้รับต้องเข้าสู่ระบบด้วย Google Account ที่มี email ตรงกันและยอมรับก่อนจึงได้รับสิทธิ์
- **เจ้าของกระเป๋า (Owner):** ผู้มีสิทธิ์อ่าน เพิ่ม แก้ไข ลบข้อมูล และจัดการการแชร์ของ Wallet
- **ความเป็นเจ้าของกระเป๋า (Wallet Ownership):** ความสัมพันธ์ระหว่าง Wallet กับ Owner หนึ่งคน ซึ่งรุ่นแรกไม่รองรับการโอนไปยัง User อื่น
- **จำนวนเงิน (Money Amount):** จำนวนเต็มหน่วยสตางค์ในสกุล THB ที่ใช้ใน database, API และการคำนวณ เพื่อหลีกเลี่ยงความคลาดเคลื่อนจาก floating point
- **เขตเวลาของกระเป๋า (Wallet Timezone):** IANA timezone `Asia/Bangkok` ที่ backend ใช้กำหนดวันและเดือนของ Transaction และรายงานให้ตรงกันทุกอุปกรณ์
- **วันที่เกิดรายการ (Occurred On):** วันที่ท้องถิ่นที่ Transaction เกิดขึ้นจริง เป็นค่าบังคับ แก้ไขได้ และใช้จัดกลุ่มรายงาน
- **เวลาเกิดรายการ (Occurred Time):** เวลาท้องถิ่นที่ Transaction เกิดขึ้นจริง เป็นค่าทางเลือกและไม่ต้องกรอกเมื่อผู้ใช้จำเวลาไม่ได้
- **เวลาสร้างข้อมูล (Created At):** UTC timestamp ที่ระบบกำหนดเมื่อสร้างข้อมูลและผู้ใช้แก้ไขไม่ได้
- **เวลาแก้ไขล่าสุด (Updated At):** UTC timestamp ที่ระบบอัปเดตเมื่อข้อมูลถูกแก้ไข
- **ตัวบอกการแก้ไขรายการ (Transaction Edit Indicator):** ข้อความแสดงเวลาที่รายการถูกแก้ล่าสุดโดยไม่เก็บหรือแสดงค่าก่อนแก้ไข
- **ผู้รับแชร์ (Viewer):** ผู้ที่อ่านรายละเอียดทั้งหมดและข้อมูลล่าสุดของ Wallet ที่ได้รับสิทธิ์ แต่สร้าง แก้ไข หรือลบข้อมูลไม่ได้
- **การแชร์แบบอ่านอย่างเดียว (Read-only Share):** การให้ Viewer เข้าถึงรายละเอียดทั้งหมดของ Wallet แบบต่อเนื่องจนกว่าจะถูกถอนสิทธิ์ โดยไม่มีสิทธิ์เปลี่ยนแปลงข้อมูล
- **เซสชัน (Session):** สถานะการเข้าสู่ระบบที่ backend ตรวจสอบและสามารถหมดอายุหรือถูกเพิกถอนได้
- **การหมดอายุแบบเลื่อนตามการใช้งาน (Rolling Session Expiry):** นโยบายที่ต่อวันหมดอายุเมื่อมีการใช้งาน และบังคับเข้าสู่ระบบใหม่เมื่อ Session ไม่มีการใช้งานครบ 7 วัน
- **การลบบัญชี (Account Deletion):** workflow ที่ต้องได้รับการยืนยันจากผู้ใช้ก่อนจัดการบัญชี Wallet ความสัมพันธ์ คำเชิญ และ Session ที่เกี่ยวข้องทั้งหมด
- **สถานะรอลบบัญชี (Pending Deletion):** ช่วงกู้คืน 30 วันที่บัญชีและการแชร์ถูกปิดใช้ทันที แต่เจ้าของยังเข้าสู่ recovery flow เพื่อยกเลิกการลบได้
- **การแจ้งเตือนด้านความปลอดภัย (Security Notification):** อีเมลแจ้งการเชิญ การเปลี่ยนสิทธิ์ หรือสถานะบัญชี ซึ่งต้องไม่มีรายละเอียดรายการหรือจำนวนเงิน
- **รายชื่อผู้ทดสอบที่อนุญาต (Beta Allowlist):** รายการ verified Google email ที่มีสิทธิ์สร้างบัญชีใน beta environment ซึ่งแยกจากคำเชิญดู Wallet
- **การล้างข้อมูลเบตา (Beta Data Reset):** การลบข้อมูลใน beta environment ที่แจ้งผู้ทดสอบล่วงหน้าและเปิดให้ Owner export ข้อมูลก่อน โดยต้องมี safety guard ป้องกันการทำกับ production
- **คำชี้แจงความเป็นส่วนตัวช่วงเบตา (Beta Privacy Notice):** ข้อความเวอร์ชันที่ผู้ทดสอบต้องยอมรับก่อนเข้าถึงข้อมูลการเงิน โดยระบบบันทึกเวอร์ชันและเวลาที่ยอมรับฝั่ง backend
- **เส้นทางที่ต้องยืนยันตัวตน (Protected Route):** หน้า frontend หรือ API ที่เปิดได้เมื่อมี Session ที่ถูกต้องเท่านั้น โดยข้อมูลการเงินทั้งหมดอยู่ภายใต้ขอบเขตนี้
- **การนำเข้าข้อมูลจากอุปกรณ์ (Device Data Import):** การย้าย Transaction และ Savings Goal จาก `localStorage` ไปยัง Personal Wallet หลังผู้ใช้ตรวจสอบและยืนยัน โดยต้องป้องกันการนำเข้าซ้ำ
- **เครื่องหมายนำเข้าสำเร็จ (Import Marker):** ข้อมูลที่ไม่มีรายละเอียดการเงินและบอกว่าอุปกรณ์นำเข้าข้อมูลเดิมสำเร็จแล้ว เพื่อไม่ให้เสนอการนำเข้าซ้ำ
- **มาตรการยับยั้งการจับภาพ (Screen-capture Deterrence):** มาตรการลดโอกาสหรือแรงจูงใจในการบันทึกหน้าจอ ซึ่งไม่สามารถรับประกันการป้องกันได้ทุกแพลตฟอร์มหรือหยุดการใช้กล้องภายนอก
- **เมนูบัญชี (Account Menu):** เมนูที่เปิดจากส่วนโปรไฟล์หรือ avatar เพื่อแสดงชื่อ, email, ประเภทบัญชี และคำสั่งเกี่ยวกับบัญชี เช่น การออกจากระบบ โดยเป็นคนละส่วนกับเมนูตั้งค่า
- **รูปประจำตัวโปรไฟล์ (Profile Avatar):** ภาพวงกลมจาก URL ใน claim `picture` ของ Google ซึ่งใช้แทนผู้ใช้ใน Account Menu และจุดเปิดเมนู โดย fallback เป็นอักษรแรกของชื่อเมื่อไม่มี URL หรือโหลดรูปไม่สำเร็จ
- **การออกจากระบบของเซสชันปัจจุบัน (Current-Session Logout):** workflow ที่ผู้ใช้ยืนยันเพื่อเพิกถอนเฉพาะ Session ของอุปกรณ์ที่กำลังใช้งานและลบ session cookie โดยไม่กระทบ Session บนอุปกรณ์อื่น
