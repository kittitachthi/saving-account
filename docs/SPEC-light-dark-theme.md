# ฟีเจอร์ธีมสว่างและธีมมืด

## Problem Statement

ผู้ใช้ต้องใช้งานแอปจัดการการเงินในสภาพแสงที่แตกต่างกัน แต่ปัจจุบันหน้าจอมีเพียงรูปแบบสีเดียว ทำให้การใช้งานในที่มืดไม่สบายตา และไม่มีวิธีเลือกหรือจดจำรูปแบบสีที่ผู้ใช้ต้องการ

ผู้ใช้ต้องการให้แอปเลือก Theme ที่เหมาะสมจากระบบในครั้งแรก พร้อมเปิดโอกาสให้เปลี่ยน Theme เองจาก Settings Surface และรักษาค่านั้นไว้อย่างสอดคล้องทั้งระหว่างการเปิดแอปและระหว่างหลายแท็บ

## Solution

เพิ่ม Theme สองแบบ ได้แก่ `light` และ `dark` โดยคงสีเขียวซึ่งเป็นเอกลักษณ์ของแอป รวมถึงความหมายของสี Income และ Expense

เมื่อยังไม่มี Theme Preference ที่ถูกต้อง แอปจะเลือก Theme จาก System Theme เมื่อผู้ใช้เลือก Theme เอง ระบบจะจำค่าล่าสุดใน `localStorage` และใช้ค่านั้นเหนือ System Theme ในการเปิดครั้งถัดไป

ผู้ใช้เข้าถึง Theme Toggle ผ่าน Settings Surface เท่านั้น บนเดสก์ท็อป Settings Surface จะแสดงเป็น popover เหนือปุ่มตั้งค่า ส่วนมือถือจะแสดงเป็น bottom sheet จากด้านล่าง ปุ่มใช้ไอคอนเพื่อแสดง Theme ปลายทาง พร้อมข้อมูลสำหรับผู้ใช้คีย์บอร์ดและเทคโนโลยีช่วยการเข้าถึง

## User Stories

1. ในฐานะผู้ใช้ใหม่ ฉันต้องการให้แอปเริ่มด้วย Theme ตามระบบ เพื่อให้รูปแบบสีสอดคล้องกับอุปกรณ์โดยไม่ต้องตั้งค่าเอง
2. ในฐานะผู้ใช้ธีมสว่าง ฉันต้องการเห็นพื้นหลัง การ์ด ข้อความ และ controls ที่อ่านง่าย เพื่อให้จัดการการเงินได้สะดวกในพื้นที่สว่าง
3. ในฐานะผู้ใช้ธีมมืด ฉันต้องการเห็นพื้นหลัง การ์ด ข้อความ และ controls ที่สบายตา เพื่อให้ใช้งานในพื้นที่มืดได้
4. ในฐานะผู้ใช้ ฉันต้องการเปิด Settings Surface ก่อนเข้าถึงการตั้งค่าธีม เพื่อให้ navigation หลักไม่รก
5. ในฐานะผู้ใช้เดสก์ท็อป ฉันต้องการให้การตั้งค่าเปิดเป็น popover ใกล้ปุ่มตั้งค่า เพื่อให้เห็นความสัมพันธ์ระหว่างปุ่มและเนื้อหา
6. ในฐานะผู้ใช้มือถือ ฉันต้องการให้การตั้งค่าเปิดเป็น bottom sheet เพื่อให้เข้าถึง controls ได้สะดวกด้วยนิ้วโป้ง
7. ในฐานะผู้ใช้ ฉันต้องการปิด Settings Surface ด้วยการกดพื้นที่ด้านนอก เพื่อให้กลับสู่หน้าหลักได้รวดเร็ว
8. ในฐานะผู้ใช้คีย์บอร์ด ฉันต้องการปิด Settings Surface ด้วยปุ่ม Escape เพื่อควบคุมหน้าจอโดยไม่ใช้เมาส์
9. ในฐานะผู้ใช้ ฉันต้องการเลือก Theme สว่างหรือมืด เพื่อปรับหน้าจอตามสภาพแสงและความชอบ
10. ในฐานะผู้ใช้ ฉันต้องการให้ Theme Toggle แสดงดวงจันทร์ขณะใช้ธีมสว่าง เพื่อให้เข้าใจว่ากดแล้วจะเปลี่ยนเป็นธีมมืด
11. ในฐานะผู้ใช้ ฉันต้องการให้ Theme Toggle แสดงดวงอาทิตย์ขณะใช้ธีมมืด เพื่อให้เข้าใจว่ากดแล้วจะเปลี่ยนเป็นธีมสว่าง
12. ในฐานะผู้ใช้ ฉันต้องการ tooltip ที่บอกการกระทำของ Theme Toggle เพื่อไม่ต้องเดาความหมายของไอคอน
13. ในฐานะผู้ใช้ screen reader ฉันต้องการ accessible name ที่บอก Theme ปลายทาง เพื่อใช้งานปุ่มได้อย่างมั่นใจ
14. ในฐานะผู้ใช้คีย์บอร์ด ฉันต้องการเห็น focus state ที่ชัดเจน เพื่อให้ทราบว่า control ใดกำลังถูกเลือก
15. ในฐานะผู้ใช้ ฉันต้องการให้แอปจำ Theme ล่าสุด เพื่อไม่ต้องเลือกใหม่ทุกครั้งที่เปิดแอป
16. ในฐานะผู้ใช้ ฉันต้องการให้ Theme Preference มีลำดับเหนือ System Theme เพื่อไม่ให้ตัวเลือกของฉันถูกเปลี่ยนโดยระบบ
17. ในฐานะผู้ใช้ที่เปิดแอปหลายแท็บ ฉันต้องการให้การเปลี่ยน Theme ในแท็บหนึ่งมีผลกับแท็บอื่นทันที เพื่อให้ทุกหน้าต่างสอดคล้องกัน
18. ในฐานะผู้ใช้ ฉันต้องการให้แอปกลับไปใช้ System Theme เมื่อข้อมูล Theme Preference เสียหาย เพื่อให้หน้าจอยังคงใช้งานได้
19. ในฐานะผู้ใช้ ฉันต้องการให้การเปลี่ยน Theme มี animation สั้น เพื่อให้การเปลี่ยนสีรู้สึกต่อเนื่อง
20. ในฐานะผู้ใช้ที่ลดการเคลื่อนไหว ฉันต้องการให้แอปเคารพ `prefers-reduced-motion` เพื่อหลีกเลี่ยง animation ที่ไม่ต้องการ
21. ในฐานะผู้ใช้ ฉันต้องการให้สีเขียวหลักคงอยู่ในทั้งสอง Theme เพื่อให้แอปยังมีเอกลักษณ์เดิม
22. ในฐานะผู้ใช้ ฉันต้องการให้ Income ยังคงสื่อด้วยสีเขียวและ Expense ด้วยสีส้ม เพื่อไม่ให้ความหมายของข้อมูลเปลี่ยนไปตาม Theme
23. ในฐานะผู้ใช้ ฉันต้องการให้กราฟ Budget, Category breakdown และสถานะต่าง ๆ มองเห็นชัดในทั้งสอง Theme เพื่ออ่านภาพรวมการเงินได้ถูกต้อง
24. ในฐานะผู้ใช้ ฉันต้องการให้ modal, input, sidebar และ navigation รองรับทั้งสอง Theme เพื่อไม่ให้บางส่วนสว่างหรือมืดผิดจากหน้าจอส่วนอื่น
25. ในฐานะผู้ใช้ ฉันต้องการให้ Theme ที่ถูกต้องถูกใช้ตั้งแต่เริ่มแสดงหน้า เพื่อหลีกเลี่ยงการกะพริบจาก Theme ที่ไม่ตรงกับค่าของฉัน

## Implementation Decisions

- Theme domain มีค่าที่ถูกต้องเพียง `light` และ `dark`
- Theme Preference หมายถึง Theme ล่าสุดที่ผู้ใช้เลือกเองและบันทึกใน `localStorage`
- System Theme อ่านจาก media query `prefers-color-scheme: dark`
- ลำดับการเลือก Theme ตอนเริ่มต้นคือ Theme Preference ที่ถูกต้องก่อน แล้วจึงใช้ System Theme
- เมื่อค่าที่อ่านจาก `localStorage` ไม่ใช่ `light` หรือ `dark` ให้ถือว่าไม่มี Theme Preference และใช้ System Theme
- เมื่อผู้ใช้เลือก Theme แล้ว ให้บันทึก Theme Preference ใหม่ทันที
- แอปไม่มีสถานะ `system` ใน Theme Preference และไม่มี control สำหรับล้างค่าเพื่อกลับไปติดตามระบบ
- เมื่อมี Theme Preference แล้ว การเปลี่ยน System Theme ต้องไม่เปลี่ยน Theme ของแอป
- ซิงก์ Theme ระหว่างแท็บด้วย browser `storage` event โดยแท็บอื่นต้องใช้ค่าใหม่ทันที
- หาก storage event ส่งค่าที่ไม่ถูกต้อง ให้ประเมิน Theme ใหม่ด้วยกฎ fallback เดียวกับตอนเริ่มต้น
- ใช้ attribute หรือ class ระดับ document เป็นจุดควบคุม Theme เพื่อให้ทุกพื้นผิวใช้ชุด design tokens เดียวกัน
- ใช้ semantic color tokens สำหรับ background, surface, text, muted text, border, accent, Income, Expense และ chart colors แทนการกระจายค่าสีตามองค์ประกอบ
- ธีมมืดเปลี่ยนพื้นหลัง surface เส้นขอบ ข้อความ input, modal และสีกราฟ แต่คงสีเขียวของแบรนด์และความหมายสี Income/Expense
- Theme Toggle อยู่ภายใน Settings Surface และไม่แสดงโดยตรงใน navigation
- เดสก์ท็อปใช้ popover ที่สัมพันธ์กับปุ่มตั้งค่า มือถือใช้ bottom sheet จากด้านล่าง
- Settings Surface ปิดได้จากการกดพื้นที่นอก surface และปุ่ม Escape
- Theme Toggle ใช้ไอคอน Theme ปลายทาง ไม่ใช่ Theme ปัจจุบัน
- Theme Toggle ต้องเป็น native button รองรับ keyboard activation, visible focus, tooltip และ accessible name
- accessible name เปลี่ยนตามสถานะเป็น “เปลี่ยนเป็นธีมมืด” หรือ “เปลี่ยนเป็นธีมสว่าง”
- การเปลี่ยนสีใช้ animation ระยะสั้นประมาณ 200–300ms
- เมื่อ `prefers-reduced-motion: reduce` มีผล ให้ยกเลิกหรือลด animation การเปลี่ยน Theme
- การกำหนด Theme เริ่มต้นควรเกิดก่อนหรือเร็วที่สุดในขั้นตอน render เพื่อหลีกเลี่ยง flash of incorrect theme
- ฟีเจอร์ไม่มีการเปลี่ยน schema ของ Transaction และไม่กระทบการคำนวณ Balance, Income, Expense, Budget หรือ Category breakdown

## Testing Decisions

- ใช้การทดสอบระดับหน้าจอแอปเป็น testing seam หลักเพียงจุดเดียว ซึ่งเป็น seam เดิมของโครงการ
- การทดสอบต้องสังเกตพฤติกรรมที่ผู้ใช้หรือ browser มองเห็นได้ ไม่ตรวจ state ภายในหรือชื่อฟังก์ชัน
- ใช้ browser-like environment เดิมและจำลอง `matchMedia`, `localStorage` และ `storage` event เท่าที่จำเป็น
- ทดสอบว่าไม่มี Theme Preference และ System Theme สว่างแล้วแอปใช้ `light`
- ทดสอบว่าไม่มี Theme Preference และ System Theme มืดแล้วแอปใช้ `dark`
- ทดสอบว่า Theme Preference มีลำดับเหนือ System Theme ที่ขัดแย้งกัน
- ทดสอบว่าค่า Theme Preference ที่ไม่ถูกต้องกลับไปใช้ System Theme
- ทดสอบการเปิด Settings Surface จากปุ่มตั้งค่า
- ทดสอบการปิด Settings Surface ด้วยพื้นที่ด้านนอกและ Escape
- ทดสอบว่า Theme Toggle แสดงไอคอนและ accessible name ของ Theme ปลายทาง
- ทดสอบว่าการกด Theme Toggle เปลี่ยน Theme และเขียนค่าที่ถูกต้องลง `localStorage`
- ทดสอบว่า storage event ที่มีค่าถูกต้องเปลี่ยน Theme ของแท็บปัจจุบันทันที
- ทดสอบว่าการเปลี่ยน System Theme หลังมี Theme Preference ไม่เขียนทับตัวเลือกผู้ใช้
- ทดสอบว่า controls หลักยังมองเห็นและใช้งานได้หลังสลับ Theme
- ทดสอบ stylesheet หรือ browser behavior ว่า reduced motion ปิด animation ที่ไม่จำเป็น
- ทดสอบ viewport เดสก์ท็อปว่า Settings Surface ใช้รูปแบบ popover
- ทดสอบ viewport มือถือว่า Settings Surface ใช้รูปแบบ bottom sheet โดยไม่มี horizontal overflow
- ทดสอบ contrast ของข้อความ controls focus indicator และข้อมูลสีสำคัญในทั้งสอง Theme ด้วยเครื่องมือตรวจ accessibility หรือการตรวจใน browser
- ชุดทดสอบของ Transaction เดิมต้องผ่านทั้งหมดเพื่อยืนยันว่าฟีเจอร์ Theme ไม่ทำให้พฤติกรรมการเงินถดถอย

## Out of Scope

- Theme มากกว่าสองรูปแบบ
- การเลือกสี accent โดยผู้ใช้
- โหมด `system` ที่ผู้ใช้เลือกกลับมาได้จาก UI
- การซิงก์ Theme Preference ข้ามอุปกรณ์หรือผ่านบัญชีผู้ใช้
- การเก็บ Theme Preference ในฐานข้อมูลหรือ API
- การกำหนด Theme แยกตามหน้า
- การปรับความสว่างหรือ contrast แบบกำหนดเอง
- การเปลี่ยนโครงสร้างหรือข้อมูล Transaction
- การแก้ไขพฤติกรรมทางการเงินอื่นนอกเหนือจากการแสดงผลตาม Theme

## Further Notes

- รูปแบบ popover บนเดสก์ท็อปและ bottom sheet บนมือถือเป็นการตัดสินใจสำหรับทดลองใช้ ควรประเมินความค้นพบง่ายและความสะดวกหลังใช้งานจริง
- การใช้สีต้องไม่เป็นวิธีเดียวในการสื่อความหมายของ Income และ Expense; เครื่องหมาย ไอคอน และข้อความเดิมควรยังคงอยู่
- `localStorage` เป็นข้อมูลเฉพาะ origin, browser และอุปกรณ์ ไม่ใช่การตั้งค่าระดับบัญชีผู้ใช้
- สเปกนี้สอดคล้องกับ ADR-003 และใช้คำศัพท์ Theme, Theme Preference, System Theme, Settings Surface และ Theme Toggle จาก domain glossary
