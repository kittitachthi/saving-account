# ADR-013: มาสคอตโต้ตอบบน Dashboard

## สถานะ

เสนอ

## บริบท

Pocka ใช้มาสคอตรูปกระเป๋าเพื่อทำให้การจดเงินเข้าถึงง่ายและไม่น่าเบื่อ แต่ปัจจุบันมาสคอตปรากฏเฉพาะหน้า Marketing ขณะที่หน้า Dashboard ซึ่งเป็นพื้นที่ทำรายการหลักยังใช้สัญลักษณ์ `฿` แบบตกแต่งและแสดงเปอร์เซ็นต์เปรียบเทียบรายเดือนที่เป็นค่าคงที่

ผู้ใช้ต้องการให้มาสคอตเป็นส่วนหนึ่งของประสบการณ์บันทึกรายรับ รายจ่าย และเงินเก็บ พร้อมตอบสนองอย่างเป็นมิตรโดยไม่ตัดสินพฤติกรรมทางการเงิน เมนู Feature ที่ยังไม่มีหน้าจริงควรสื่อว่ายังไม่พร้อมใช้งานแทนการหายไปจาก Navigation

## การตัดสินใจ

### ตำแหน่งและภาพลักษณ์

- วางมาสคอตในพื้นที่ด้านขวาของการ์ด “ยอดเงินพร้อมใช้” แทนเครื่องหมาย `฿` ขนาดใหญ่ในวงแหวนเดิม
- คงเครื่องหมาย `฿` หน้าเลขยอดเงินเพื่อระบุหน่วยเงินอย่างชัดเจน
- จุดยึดและพื้นที่หลักของมาสคอตอยู่ภายในการ์ด แต่ภาพสามารถล้นขอบบนหรือขอบข้างได้เล็กน้อยเพื่อสร้างมิติ
- Layout ต้องสำรองพื้นที่ให้ส่วนที่ล้นออกมา ไม่ทับการ์ดอื่น ตัวเลข ปุ่ม หรือ Hit Target และต้องตอบสนองต่อหน้าจอมือถือ
- ใช้รูปแบบตัวละคร สี และบุคลิกเดียวกับมาสคอตหน้า Marketing

### Mascot State Model

มาสคอตมีสถานะ UI ชั่วคราวดังนี้:

| สถานะ | เหตุการณ์ที่ทำให้เข้าสู่สถานะ | การแสดงผล | ทางออก |
| --- | --- | --- | --- |
| `idle` | เปิดหน้า, interaction สิ้นสุด, ผู้ใช้กลับมาใช้งาน | ยิ้มและขยับตัวเบา ๆ ไม่มีข้อความ | รับเหตุการณ์ใหม่หรือไม่มี Activity ครบ 60 วินาที |
| `income` | เพิ่มรายรับสำเร็จ | ดีใจพร้อมเหรียญหรือประกายสีเขียว และข้อความ “เงินเข้าแล้ว เยี่ยมเลย!” | กลับ `idle` หลัง 4 วินาที |
| `expense` | เพิ่มรายจ่ายสำเร็จ | ถือใบเสร็จด้วยสีหน้าเป็นมิตร และข้อความ “รับรู้แล้ว เดี๋ยวเราช่วยดูให้นะ” | กลับ `idle` หลัง 4 วินาที |
| `saving` | เพิ่มเงินเก็บสำเร็จ | ฉลองด้วยดาวหรือประกายพิเศษ และข้อความ “เข้าใกล้เป้าหมายอีกนิด!” | กลับ `idle` หลัง 4 วินาที |
| `sleeping` | หน้าเว็บมองเห็นอยู่และไม่มี Activity ครบ 60 วินาที | หลับพร้อมตัว `Z` ไม่มีข้อความ | กลับ `idle` ทันทีเมื่อมี Activity |
| `error` | เพิ่มรายรับ รายจ่าย หรือเงินเก็บไม่สำเร็จ | เป็นห่วงเล็กน้อยและข้อความ “ยังบันทึกไม่ได้ ลองอีกครั้งนะ” | กลับ `idle` ตาม Feedback lifecycle หรือเมื่อเริ่มการกระทำใหม่ |

ลำดับความสำคัญของสถานะคือ `error` → ปฏิกิริยาจากรายการที่บันทึกสำเร็จ → `sleeping` → `idle` เหตุการณ์ใหม่แทนที่ปฏิกิริยาเดิมทันทีและเริ่มเวลา 4 วินาทีใหม่ โดยไม่ต่อคิว Animation

สถานะมาสคอตไม่ใช่ข้อมูลทางการเงิน ไม่บันทึกลงฐานข้อมูลหรือ Local Storage และเริ่มต้นใหม่เมื่อ Refresh หน้า

### Activity และ AFK

- Activity ได้แก่ pointer, touch, keyboard และ scroll ที่เกิดขึ้นขณะหน้าเว็บมองเห็นอยู่
- นับ AFK เฉพาะเมื่อ `document.visibilityState` เป็น `visible`
- เมื่อหน้าเว็บถูกซ่อน ให้พักและล้างตัวจับเวลา เมื่อกลับมาเห็นหน้าเว็บให้เริ่มนับ 60 วินาทีใหม่
- Activity ใด ๆ ระหว่าง `sleeping` ทำให้มาสคอตตื่นและกลับ `idle` ทันที
- การลบรายการ การลบเงินเก็บ การเปลี่ยน Theme และการเปิดหรือปิด Surface ไม่เปลี่ยนสถานะมาสคอตในขอบเขตนี้

### Motion และการเข้าถึง

- Animation ต้องเป็นการเคลื่อนไหวเบา ๆ ไม่บังข้อมูลและไม่ขัดขวางการทำรายการ
- เมื่อ `prefers-reduced-motion: reduce` ให้คงการเปลี่ยนภาพ สีหน้า และข้อความ แต่ตัดการกระโดด เลื่อน หมุน ขยาย และการเคลื่อนไหวซ้ำ
- ภาพมาสคอตเป็นส่วนประกอบเชิงนำเสนอ ส่วนข้อความ Feedback เป็นความหมายหลักและต้องอ่านได้โดยไม่พึ่งภาพหรือสี
- หลีกเลี่ยงสีแดง สีหน้ารุนแรง หรือถ้อยคำตำหนิสำหรับรายจ่าย เพราะการบันทึกรายจ่ายเป็นพฤติกรรมที่ระบบต้องสนับสนุน

### Navigation ที่ยังไม่พร้อม

- คงเมนู `รายการทั้งหมด`, `งบประมาณ` และ `รายงาน` ไว้เพื่อสื่อทิศทางของผลิตภัณฑ์
- แสดงป้าย `เร็ว ๆ นี้` ลด Visual Emphasis และไม่มี Navigation หรือ Side Effect เมื่อกด
- ระบุ `aria-disabled="true"` และไม่นำ Control ที่ใช้งานไม่ได้เข้า Tab Order
- ป้ายข้อความต้องมองเห็นได้บน Desktop และ Mobile โดยไม่อาศัย Hover Tooltip เพียงอย่างเดียว
- `ภาพรวม`, `ตั้งค่า` และเมนูบัญชียังคงใช้งานได้ตามเดิม

### ข้อมูลเปรียบเทียบที่ยังไม่มี Source of Truth

- ซ่อน `8.4% จากเดือนที่แล้ว` บนการ์ดยอดเงินพร้อมใช้
- ซ่อน `12.5%` บนการ์ดรายรับเดือนนี้และ `3.2%` บนการ์ดรายจ่ายเดือนนี้
- คงยอดเงินที่คำนวณจากข้อมูลจริงไว้
- จะนำเปอร์เซ็นต์กลับมาเมื่อกำหนดช่วงเวลา วิธีคำนวณ สถานะไม่มีข้อมูล และ Source of Truth ที่ทดสอบได้แล้วเท่านั้น

## ผลที่ตามมา

- Dashboard มีบุคลิกสอดคล้องกับหน้า Marketing และให้ Feedback หลังทำรายการอย่างชัดเจน
- ต้องมี Asset หรือ Presentation Variant สำหรับมาสคอตหกสถานะ และมี State Orchestration ที่แยกจาก Domain Data
- ต้องจัดการ Timer, Page Visibility และ Event Listener โดย Cleanup เมื่อ Component ถูกถอด
- การทดสอบต้องใช้เวลาจำลอง ตรวจการแทนที่สถานะล่าสุด การพัก AFK เมื่อซ่อนหน้า และ Reduced Motion
- Feature ที่ยังไม่พร้อมจะมองเห็นได้ แต่ต้องไม่ถูกเข้าใจผิดว่าใช้งานได้แล้ว

## ขอบเขตที่ไม่รวม

- ปฏิกิริยาจากการแก้ไขหรือลบรายการ
- การคลิก เล่น หรือให้อาหารมาสคอต
- การสุ่มข้อความหรือบุคลิกที่ปรับตามผู้ใช้
- การเก็บสถานะมาสคอตข้าม Session หรือข้ามอุปกรณ์
- การคำนวณเปอร์เซ็นต์เปรียบเทียบรายเดือน
- การสร้างหน้า `รายการทั้งหมด`, `งบประมาณ` หรือ `รายงาน`
