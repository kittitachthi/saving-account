# ADR-007: แยกเงินเก็บออกจากยอดเงินพร้อมใช้

## สถานะ

กำลังพิจารณา

## บริบท

ระบบเดิมรองรับรายการรายรับและรายจ่าย โดยคำนวณยอดคงเหลือจากรายรับรวมลบรายจ่ายรวม ผู้ใช้ต้องการกันเงินบางส่วนไว้เป็นเงินเก็บ โดยเงินส่วนนี้ยังเป็นทรัพย์สินของผู้ใช้ แต่ไม่ควรปรากฏเป็นเงินที่พร้อมนำไปใช้จ่าย

## การตัดสินใจที่ยืนยันแล้ว

- เพิ่มประเภทรายการ `saving` ควบคู่กับ `income` และ `expense`
- การเพิ่มรายการเงินเก็บลด “ยอดเงินคงเหลือ/ยอดเงินพร้อมใช้” ตามจำนวนที่เก็บ
- เงินเก็บไม่ถือเป็นรายจ่าย และต้องแสดงยอดสะสมแยกต่างหาก
- จำนวนเงินของรายการเงินเก็บใหม่ต้องมากกว่าศูนย์และต้องไม่เกินยอดเงินพร้อมใช้ ณ เวลาที่บันทึก
- จำนวนเงินของรายการรายจ่ายใหม่ต้องไม่เกินยอดเงินพร้อมใช้ ณ เวลาที่บันทึกเช่นกัน
- หากรายจ่ายหรือเงินเก็บเกินยอดพร้อมใช้ ระบบต้องปฏิเสธรายการ แสดงข้อผิดพลาดภายในฟอร์ม และระบุจำนวนเงินส่วนที่เกิน เช่น “ยอดรายจ่ายมากกว่าเงินพร้อมใช้ 1,000 บาท”
- ตัวอย่าง: เมื่อยอดพร้อมใช้เท่ากับ 30,000 บาท การเก็บเงิน 5,000 บาททำให้ยอดพร้อมใช้เหลือ 25,000 บาท และยอดเงินเก็บเพิ่มขึ้น 5,000 บาท
- ผู้ใช้สามารถกำหนด “เป้าหมายเงินเก็บ” เป็นจำนวนเงินได้
- หน้าหลักต้องมีกราฟความคืบหน้าของเงินเก็บ โดยแสดงยอดเงินเก็บรวมเทียบกับเป้าหมาย เช่น “เก็บแล้ว 5,000 บาท จากเป้า 20,000 บาท”
- ยอดเงินเก็บรวมเป็นข้อมูลคำนวณจากรายการเงินเก็บ ส่วนเป้าหมายเงินเก็บเป็นค่าที่ผู้ใช้กำหนดและจัดเก็บแยกต่างหาก
- หน้าแรกมีปุ่มสำหรับตั้งเป้าหมายเงินเก็บวางอยู่ข้างปุ่ม “เพิ่มรายการ”
- เมื่อมีเป้าหมายแล้ว ปุ่มตั้งเป้าหมายใช้เปิดการแก้ไขเป้าหมายเดิม
- เป้าหมายเงินเก็บไม่ใช่เพดาน ผู้ใช้เพิ่มเงินเก็บเกินเป้าหมายและแก้เป้าหมายให้ต่ำกว่ายอดเงินเก็บรวมได้
- เมื่อยอดเงินเก็บถึงเป้าหมาย กราฟแสดงความสำเร็จ 100%
- เมื่อยอดเงินเก็บเกินเป้าหมาย ส่วนเติมของกราฟคงไว้ที่ 100% และแสดงข้อความว่าเกินเป้าหมายกี่เปอร์เซ็นต์
- ก่อนตั้งเป้าหมาย การ์ดเงินเก็บยังแสดงยอดเงินเก็บรวม แต่ไม่แสดงเปอร์เซ็นต์ และแสดงข้อความ “ยังไม่ได้ตั้งเป้าหมาย” พร้อมทางลัดให้ตั้งเป้าหมาย
- รายการรายรับลบได้หากยอดพร้อมใช้หลังลบยังไม่ติดลบ
- หากการลบรายรับทำให้ยอดพร้อมใช้ติดลบ ระบบต้องปฏิเสธการลบและแจ้งจำนวนเงินที่ขาด
- กราฟเงินเก็บใช้รูปแบบวงแหวน โดยตรงกลางแสดงยอดเงินเก็บรวม
- วงแหวนเติมตามความคืบหน้าและจำกัดการเติมภาพไว้ที่ 100% ส่วนกรณีเกินเป้าแสดงเป็นข้อความประกอบ
- รายการเงินเก็บต้องมีหมวดหมู่ เพื่อแยกวัตถุประสงค์ของเงินที่เก็บ
- กราฟเงินเก็บต้องแสดงการแยกยอดตามหมวดหมู่เงินเก็บด้วย
- หมวดหมู่เริ่มต้นประกอบด้วย “เงินฉุกเฉิน”, “ท่องเที่ยว”, “ซื้อของชิ้นใหญ่”, “เกษียณ” และ “อื่น ๆ”
- เมื่อเลือก “อื่น ๆ” ผู้ใช้ต้องระบุชื่อหมวดหมู่เอง และชื่อดังกล่าวถูกบันทึกเป็นหมวดหมู่ของรายการ
- กราฟเงินเก็บใช้ interaction รายละเอียดแบบเดียวกับกราฟ “ภาพรวมรายจ่าย”: hover หรือ focus ส่วนสีเพื่อเปิด tooltip, เมาส์ออกหรือ blur เพื่อปิด, คลิก/แตะเพื่อสลับเปิด–ปิด และกด Escape เพื่อปิด
- ส่วนสีแต่ละส่วนเป็นเป้าหมาย interaction และ tooltip แสดงข้อมูลของหมวดเงินเก็บส่วนนั้น
- tooltip ของหมวดเงินเก็บแสดงชื่อหมวด, ยอดรวม, สัดส่วนต่อเงินเก็บทั้งหมด, จำนวนรายการ, ค่าเฉลี่ยต่อรายการ, สัดส่วนต่อเป้าหมาย และยอดรวมที่ยังขาดหรือเกินเป้าหมาย
- legend ใต้กราฟสามารถ hover, focus หรือคลิกเพื่อเปิดรายละเอียดของหมวดเดียวกันได้เหมือนส่วนสีบนกราฟ
- animation ใช้พฤติกรรมเดียวกับกราฟภาพรวมรายจ่าย: ขยายความหนาของส่วนที่ active, ลด opacity ของส่วนอื่น, เพิ่มเงา และให้ tooltip ปรากฏด้วย fade/slide ระยะสั้น
- เมื่อระบบตั้งค่า `prefers-reduced-motion: reduce` ต้องตัด animation, การขยาย และเงาออก แต่ยังคงข้อมูลและสถานะ active ที่รับรู้ได้
- เมื่อยังไม่มีเป้าหมาย tooltip ยังคงแสดงข้อมูลสรุปของหมวด แต่แทนฟิลด์สัดส่วนและสถานะต่อเป้าหมายด้วยข้อความ “ยังไม่ได้ตั้งเป้าหมาย”

## สมการโดเมนเบื้องต้น

- `ยอดพร้อมใช้ = รายรับรวม - รายจ่ายรวม - เงินเก็บรวม`
- `เงินเก็บรวม = ผลรวมของรายการประเภท saving`
- เงื่อนไขการเพิ่มเงินเก็บ: `0 < จำนวนเงินที่จะเก็บ <= ยอดพร้อมใช้ก่อนบันทึก`
- เงื่อนไขการเพิ่มรายจ่าย: `0 < จำนวนรายจ่าย <= ยอดพร้อมใช้ก่อนบันทึก`
- `จำนวนที่เกิน = จำนวนเงินในรายการ - ยอดพร้อมใช้ก่อนบันทึก`
- `เปอร์เซ็นต์ความคืบหน้า = (เงินเก็บรวม / เป้าหมายเงินเก็บ) * 100`
- `เปอร์เซ็นต์ที่เกินเป้าหมาย = ((เงินเก็บรวม - เป้าหมายเงินเก็บ) / เป้าหมายเงินเก็บ) * 100`
- เงื่อนไขการลบรายรับ: `ยอดพร้อมใช้หลังลบ >= 0`

## ประเด็นที่ยังต้องตัดสินใจ

- วิธีแสดงทั้งความคืบหน้าต่อเป้าหมายและสัดส่วนหมวดหมู่ในกราฟเดียวกัน
- ขอบเขตของการถอนหรือย้ายเงินออกจากเงินเก็บ
- ความหมายของคำว่า “เงินทั้งหมด” บนหน้าหลักหลังแยกยอดเงินเก็บ

## ผลกระทบที่คาดไว้

โมเดลยอดรวม ฟอร์มเพิ่มรายการ ตัวกรองรายการ การจัดเก็บข้อมูล และหน้าสรุปต้องรองรับประเภทรายการใหม่ โดยยอดเงินเก็บควรเป็นข้อมูลคำนวณจากรายการซึ่งเป็นแหล่งข้อมูลจริงเพียงชุดเดียว
