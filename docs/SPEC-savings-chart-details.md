# รายละเอียดแบบโต้ตอบของกราฟเงินเก็บ

## Problem Statement

กราฟเงินเก็บแสดงยอดรวม ความคืบหน้า และสีของหมวดหมู่ แต่ผู้ใช้ยังไม่สามารถตรวจสอบรายละเอียดของแต่ละหมวดจากกราฟได้โดยตรง จึงต้องเพิ่ม interaction และข้อมูลสรุปที่สอดคล้องกับกราฟภาพรวมรายจ่ายเดิม

### Implementation Gap ที่ตรวจพบ

แม้ส่วนสีของกราฟเป้าหมายเงินเก็บจะปรากฏแล้ว แต่การ hover ส่วนสีในพฤติกรรมปัจจุบันไม่แสดง animation และไม่เปิด tooltip ตามกราฟภาพรวมรายจ่าย ข้อนี้ถือเป็น defect ต่อสเปก ไม่ใช่ interaction รูปแบบใหม่

จากการตรวจโครงสร้างพบว่า Presentation Overlay ซึ่งแสดงยอดเงินตรงกลางครอบพื้นที่กราฟและยังรับ pointer events อยู่ ทำให้ event จาก hover และ click ไปไม่ถึง Donut Segment ที่อยู่ด้านล่าง ทั้งสอง interaction จึงไม่ตอบสนองจากสาเหตุเดียวกัน

## Solution

ทำให้ส่วนสีและ legend ของแต่ละหมวดเงินเก็บเปิด tooltip ได้ด้วย hover, focus, click หรือ tap โดยใช้รูปแบบภาพและ animation เดียวกับกราฟภาพรวมรายจ่าย รองรับคีย์บอร์ด จอสัมผัส และ reduced motion

## Domain Model

`Savings Category Summary` เป็น derived data จากรายการประเภท `saving` ประกอบด้วย:

- `name`: ชื่อหมวดเงินเก็บ
- `total`: ยอดเงินเก็บรวมของหมวด
- `count`: จำนวนรายการในหมวด
- `average`: ค่าเฉลี่ยต่อรายการ หรือ `total / count`
- `shareOfSavings`: สัดส่วนของหมวดต่อเงินเก็บรวม หรือ `(total / savingsTotal) * 100`
- `shareOfGoal`: สัดส่วนของหมวดต่อเป้าหมาย หรือ `(total / savingsGoal) * 100`; ไม่มีค่าเมื่อยังไม่ตั้งเป้าหมาย
- `goalDifference`: ผลต่างระดับภาพรวม `savingsTotal - savingsGoal`; ค่าลบหมายถึงยังขาด ค่าบวกหมายถึงเกินเป้าหมาย
- `offset`: ตำแหน่งเริ่มต้นของส่วนสีบนวงแหวน

ข้อมูลทั้งหมดต้องคำนวณจาก Transaction ซึ่งเป็น source of truth และ Savings Goal โดยไม่เก็บค่าผลรวมซ้ำใน state หรือ storage

## Tooltip Content

เรียงข้อมูลดังนี้:

1. ชื่อหมวด
2. ยอดรวมของหมวด
3. สัดส่วนต่อเงินเก็บทั้งหมด
4. จำนวนรายการ
5. ค่าเฉลี่ยต่อรายการ
6. สัดส่วนของหมวดต่อเป้าหมายเงินเก็บ
7. ยอดเงินรวมที่ยังขาดจากเป้าหมาย หรือยอดและเปอร์เซ็นต์ที่เกินเป้าหมาย

หากยังไม่มี Savings Goal ให้แสดงข้อ 1–5 ตามปกติ และแสดง “ยังไม่ได้ตั้งเป้าหมาย” แทนข้อ 6–7

## Interaction Rules

- Hover หรือ focus ส่วนสีเปิด tooltip ของหมวดนั้น
- Hover ต้องตอบสนองทันทีบนพื้นที่ stroke ที่มองเห็นได้ทั้งหมดของส่วนนั้น โดยไม่ต้องคลิกก่อน
- ชั้นข้อความหรือองค์ประกอบตกแต่งที่วางทับ SVG ต้องไม่รับ pointer events; Donut Segment ต้องเป็น hit target ของพื้นที่ส่วนสี
- Mouse leave หรือ blur ปิด tooltip
- Click/tap ส่วนสีหรือ legend สลับเปิด–ปิด tooltip
- กด Enter หรือ Space บนส่วนสีที่ focus เพื่อสลับ tooltip
- กด Escape หรือแตะพื้นที่ด้านนอกเพื่อปิด tooltip
- เมื่อหมวดหนึ่ง active ให้เพิ่มความหนาและเงาของส่วนนั้น พร้อมลด opacity ของส่วนอื่น
- Tooltip ปรากฏด้วย fade/slide ระยะสั้นแบบเดียวกับกราฟภาพรวมรายจ่าย
- Legend มี hover/focus feedback และเปิดหมวดเดียวกับส่วนสีที่เชื่อมโยงกัน
- เมื่อ `prefers-reduced-motion: reduce` ให้ปิด animation, การขยาย และ drop shadow โดยไม่ตัดเนื้อหาหรือ keyboard interaction

## Acceptance Criteria

1. เมื่อชี้ส่วนสีของหมวด Tooltip แสดงข้อมูลตรงกับรายการเงินเก็บในหมวดนั้น
2. การชี้ส่วนสีเพียงอย่างเดียวทำให้ส่วนดังกล่าวหนาขึ้นและมีเงาทันที โดยไม่ต้อง click หรือ focus ก่อน
3. เปอร์เซ็นต์ต่อเงินเก็บรวมและต่อเป้าหมายคำนวณจากยอดจริง
4. จำนวนรายการและค่าเฉลี่ยเปลี่ยนตามการเพิ่ม ลบ หรือ Undo รายการเงินเก็บ
5. เมื่อยอดรวมต่ำกว่าเป้าหมาย Tooltip แสดงจำนวนที่ยังขาด
6. เมื่อยอดรวมเกินเป้าหมาย Tooltip แสดงทั้งจำนวนและเปอร์เซ็นต์ที่เกิน
7. เมื่อยังไม่มีเป้าหมาย Tooltip แสดง “ยังไม่ได้ตั้งเป้าหมาย” และไม่มีการหารด้วยศูนย์หรือแสดง `NaN`
8. การ hover, focus, keyboard, click/tap และ dismiss ทำงานตามกฎเดียวกับกราฟภาพรวมรายจ่าย
9. Reduced motion ปิด motion effects แต่ Tooltip และสถานะ active ยังใช้งานได้
10. Tooltip ไม่ล้น viewport หรือบังข้อมูลสำคัญบนหน้าจอมือถือ
11. การชี้หรือคลิกส่วนสีทำงานได้แม้ตำแหน่ง pointer อยู่ใต้ขอบเขตของข้อความตรงกลางหรือ Presentation Overlay

## Out of Scope

- การแก้ไขหรือลบรายการจากภายใน tooltip
- การเปลี่ยนเป้าหมายจาก tooltip
- กราฟย้อนหลังตามวันหรือเดือน
- การสร้าง animation รูปแบบใหม่ที่ต่างจากกราฟภาพรวมรายจ่าย
