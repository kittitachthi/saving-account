# สเปก: กระแสเงินวันนี้และ Pagination รายการธุรกรรม

## Problem Statement

การ์ดงบประมาณคงเหลือใช้วงเงินตัวอย่างที่ผู้ใช้ยังตั้งค่าเองไม่ได้ จึงไม่ช่วยให้เข้าใจสถานะการเงินจริงมากนัก ผู้ใช้ต้องการเห็นรายรับเทียบรายจ่ายของวันนี้ในทันที พร้อมรายละเอียดเมื่อสนใจ ส่วนรายการธุรกรรมมีจำนวนเพิ่มขึ้นจนการแสดงรายการทั้งหมดในพื้นที่เดียวทำให้ค้นหารายการเก่ายาก นอกจากนี้ข้อมูลเดิมใช้ข้อความวันที่ เช่น `วันนี้` ซึ่งไม่สามารถคำนวณวันจริงหรือเปลี่ยนวันอัตโนมัติได้

## Solution

แทนที่การ์ดงบประมาณด้วยการ์ด `รายรับเทียบรายจ่ายวันนี้` ซึ่งใช้รายการ `income` และ `expense` ของวันท้องถิ่นปัจจุบัน แสดงเป็นแถบแนวนอนสีเขียวและแดงที่รวมกันเป็น 100% และมี Tooltip ที่สอดคล้องกับระบบกราฟกลาง

เปลี่ยน Transaction รูปแบบใหม่ให้เก็บ `createdAt` เป็น source of truth ล้างข้อมูล mock/schema เดิมแบบ one-time reset และคำนวณป้ายวันจากเวลาจริง พร้อมแบ่งรายการธุรกรรมหลังกรองเป็นหน้า หน้าละ 10 รายการ

## User Stories

1. As a ผู้ใช้ ฉันต้องการเห็นการ์ดรายรับเทียบรายจ่ายวันนี้ เพื่อประเมินกระแสเงินของวันนี้ได้ทันที
2. As a ผู้ใช้ ฉันต้องการเห็นยอดรายรับวันนี้โดยไม่ต้อง hover เพื่ออ่านข้อมูลสำคัญได้รวดเร็ว
3. As a ผู้ใช้ ฉันต้องการเห็นยอดรายจ่ายวันนี้โดยไม่ต้อง hover เพื่ออ่านข้อมูลสำคัญได้รวดเร็ว
4. As a ผู้ใช้ ฉันต้องการเห็นแถบแนวนอนแบ่งตามสัดส่วนรายรับและรายจ่าย เพื่อเข้าใจความสัมพันธ์ของยอดทั้งสอง
5. As a ผู้ใช้ ฉันต้องการให้สัดส่วนรายรับและรายจ่ายรวมกันเป็น 100% เพื่อไม่ให้ตีความกราฟผิด
6. As a ผู้ใช้ ฉันต้องการให้รายรับเป็นสีเขียวเสมอ เพื่อจำแนกเงินเข้าได้ชัดเจน
7. As a ผู้ใช้ ฉันต้องการให้รายจ่ายเป็นสีแดงเสมอ เพื่อจำแนกเงินออกได้ชัดเจน
8. As a ผู้ใช้ ฉันต้องการให้สีไม่เปลี่ยนตามตำแหน่งของ segment แม้มีเพียงฝั่งเดียว เพื่อให้ความหมายของสีคงที่
9. As a ผู้ใช้ ฉันต้องการให้การ์ดไม่นับรายการเงินเก็บ เพื่อแยกเงินเก็บออกจากกระแสเงินใช้จ่ายตามนิยามระบบ
10. As a ผู้ใช้ ฉันต้องการเห็นข้อความยังไม่มีรายการวันนี้เมื่อวันนี้ไม่มีรายรับและรายจ่าย เพื่อเข้าใจว่า 0 บาทเกิดจากไม่มีข้อมูล
11. As a ผู้ใช้ ฉันต้องการเห็นฝั่งเดียวเป็น 100% เมื่อมีรายการเพียงประเภทเดียว เพื่อให้สัดส่วนสะท้อนข้อมูลจริง
12. As a ผู้ใช้ ฉันต้องการเปิด Tooltip ของรายรับด้วย hover/focus เพื่อดูข้อมูลเชิงลึกของเงินเข้า
13. As a ผู้ใช้ ฉันต้องการเปิด Tooltip ของรายจ่ายด้วย hover/focus เพื่อดูข้อมูลเชิงลึกของเงินออก
14. As a ผู้ใช้ ฉันต้องการเปิดรายละเอียดของฝั่ง 0% จากป้ายยอด เพื่อยังเข้าถึงข้อมูลได้แม้ไม่มีพื้นที่บนแถบ
15. As a ผู้ใช้ ฉันต้องการให้ Tooltip แสดงประเภท ยอดรวม เปอร์เซ็นต์ และจำนวนรายการ เพื่อประเมินข้อมูลได้ครบ
16. As a ผู้ใช้ ฉันต้องการเห็นรายการมูลค่าสูงสุดของฝั่งนั้น เพื่อค้นหารายการที่มีผลต่อยอดมากที่สุด
17. As a ผู้ใช้ ฉันต้องการเห็นรายการมูลค่าสูงสุดทุกแถวเมื่อยอดเท่ากัน เพื่อไม่ให้ข้อมูลการเงินถูกละทิ้ง
18. As a ผู้ใช้ ฉันต้องการให้รายการมูลค่าสูงสุดเรียงใหม่สุดก่อน เพื่อดูรายการล่าสุดก่อน
19. As a ผู้ใช้ ฉันต้องการตรึง Tooltip ด้วยการคลิกหรือแตะ เพื่ออ่านข้อมูลต่อเนื่องได้
20. As a ผู้ใช้ ฉันต้องการให้ Pinned Tooltip เลื่อนดูรายการยอดสูงสุดทั้งหมดได้ เมื่อข้อมูลล้นพื้นที่หน้าจอ
21. As a ผู้ใช้ ฉันต้องการให้ hover Tooltip แจ้งว่าคลิกเพื่อดูทั้งหมดเมื่อข้อมูลล้น เพื่อรู้วิธีเข้าถึงข้อมูลที่เหลือ
22. As a ผู้ใช้ ฉันต้องการให้ Tooltip ตาม pointer และหยุดเมื่อถูก pin เพื่อควบคุมตำแหน่งการอ่าน
23. As a ผู้ใช้ ฉันต้องการใช้ Enter, Space และ Escape กับการ์ด เพื่อใช้งานโดยไม่พึ่งเมาส์
24. As a ผู้ใช้ ฉันต้องการให้การคลิกภายใน Pinned Tooltip ไม่ปิดข้อมูล เพื่อเลื่อนหรืออ่านได้โดยไม่ถูกรบกวน
25. As a ผู้ใช้ ฉันต้องการให้การ์ดอ้างอิงวันท้องถิ่นของ browser เพื่อให้คำว่า “วันนี้” ตรงกับพื้นที่ของฉัน
26. As a ผู้ใช้ ฉันต้องการให้การ์ดเปลี่ยนวันอัตโนมัติเมื่อเปิดแอปข้ามเที่ยงคืน เพื่อไม่ต้อง refresh เอง
27. As a ผู้ใช้ ฉันต้องการให้ Transaction ใหม่เก็บเวลาจริง เพื่อใช้คำนวณวันและลำดับได้ถูกต้อง
28. As a ผู้ใช้ ฉันต้องการให้รายการวันนี้แสดง `วันนี้` และรายการเมื่อวานแสดง `เมื่อวาน` เพื่ออ่านง่าย
29. As a ผู้ใช้ ฉันต้องการให้รายการเก่าแสดงวันที่ภาษาไทย เพื่อระบุวันย้อนหลังได้ชัดเจน
30. As a ผู้ใช้ ฉันต้องการเริ่มจากรายการว่างหลังล้าง mock/schema เดิม เพื่อทดสอบระบบด้วยข้อมูลของตัวเอง
31. As a ผู้ใช้ ฉันต้องการเห็นข้อความ `ยังไม่มีรายการธุรกรรม` เมื่อไม่มีรายการ เพื่อเข้าใจสถานะระบบ
32. As a ผู้ใช้ ฉันต้องการเห็นรายการใหม่สุดก่อน เพื่อเข้าถึงรายการล่าสุดได้ทันที
33. As a ผู้ใช้ ฉันต้องการกรองรายการตามทั้งหมด รายรับ รายจ่าย หรือเงินเก็บก่อนแบ่งหน้า เพื่อค้นหาประเภทธุรกรรมได้ง่าย
34. As a ผู้ใช้ ฉันต้องการเห็นรายการไม่เกิน 10 รายการต่อหน้า เพื่อให้หน้าจออ่านง่าย
35. As a ผู้ใช้ ฉันต้องการใช้เลขหน้าและปุ่มก่อนหน้า/ถัดไป เพื่อย้อนดูรายการเก่าได้ตรงจุด
36. As a ผู้ใช้ ฉันต้องการให้ Pagination ซ่อนเมื่อมีไม่เกิน 10 รายการ เพื่อไม่ให้ UI รก
37. As a ผู้ใช้ ฉันต้องการกลับหน้า 1 เมื่อเปลี่ยนตัวกรองหรือเพิ่มรายการ เพื่อเริ่มดูผลลัพธ์ชุดใหม่จากต้นรายการ
38. As a ผู้ใช้ ฉันต้องการให้หน้าปรับไปหน้าสุดท้ายเมื่อลบจนหน้าปัจจุบันว่าง เพื่อไม่เห็นหน้าที่ไม่มีข้อมูลโดยไม่จำเป็น
39. As a ผู้ใช้ ฉันต้องการให้ Undo รักษาหน้าปัจจุบันเมื่อยังถูกต้อง เพื่อไม่เสียตำแหน่งที่กำลังอ่าน
40. As a ผู้ใช้ ฉันต้องการให้การ์ดและ Pagination ปรับข้อมูลทันทีหลังเพิ่ม ลบ หรือกรอง เพื่อให้ภาพรวมไม่ล้าสมัย

## Implementation Decisions

- Transaction รูปแบบใหม่มี `createdAt` เป็น ISO timestamp และใช้แทนข้อความวันที่ในการคำนวณวันและการเรียงลำดับ
- Storage เปลี่ยนเป็น schema ใหม่ ล้าง key เดิมและไม่ทำ migration เพราะข้อมูลเดิมเป็น mock
- seed เริ่มต้นเป็นรายการว่าง
- การคำนวณวันใช้วันปฏิทินตาม timezone ของ browser และมี lifecycle ตรวจขอบเขตวันระหว่างเปิดแอป
- Daily Cashflow Summary เป็น Derived Data ที่รวมเฉพาะ `income` และ `expense` ของวันนี้ โดยไม่นับ `saving`
- Cashflow Segment มี type, total, percentage, count และชุด highest-value transactions
- สัดส่วนคำนวณจาก `total / (income total + expense total)` และใช้ 0/0 เมื่อไม่มีรายการ
- สีเป็น semantic mapping ตามประเภท ไม่อิง `:last-child` หรือ index ของ segment: income เขียว, expense แดง
- แถบและป้ายยอดของทั้งสองฝั่งเป็น interactive triggers
- Tooltip ใช้ shared floating positioning และ interaction contract เดียวกับกราฟเดิม
- Hover Tooltip ไม่รับ pointer events; Pinned Tooltip รับ pointer events และ scroll ได้
- รายการมูลค่าสูงสุดที่เท่ากันต้องแสดงครบ เรียงด้วย `createdAt` ใหม่สุดก่อน และใช้ id เป็นลำดับรอง
- Filtered Transactions คือผลลัพธ์หลังกรองและเรียง ก่อนตัดเป็นหน้า
- Transaction Page มีขนาด 10 รายการ เลขหน้าปัจจุบัน และจำนวนหน้าทั้งหมด
- เพิ่มรายการและเปลี่ยน filter reset ไปหน้า 1; การลบปรับ current page ให้อยู่ในหน้าที่มีข้อมูล; Undo ไม่ reset หากหน้าปัจจุบันยัง valid
- ไม่เพิ่มการตั้งงบประมาณ ไม่รวมเงินเก็บในกราฟนี้ และไม่ทำ server-side persistence

## Testing Decisions

- ทดสอบพฤติกรรมภายนอกที่ผู้ใช้เห็นเป็นหลักผ่าน App integration seam เดียว: การ์ด สี สัดส่วน Tooltip pin/hover/keyboard/touch, empty state, day rollover, filter และ Pagination
- ทดสอบ pure domain seam เฉพาะสูตรที่ควบคุมด้วยเวลาและกรณีขอบ: local-day matching, 0/0, percentage, highest ties, stable sorting และ pagination slicing
- ทดสอบ storage adapter ว่า schema เก่าถูกล้างและรายการใหม่ที่มี `createdAt` ถูกบันทึก/โหลด
- ใช้แนวทางเดียวกับ integration tests ของกราฟและ transaction domain tests ที่มีอยู่ โดยไม่ผูก test กับชื่อ CSS หรือโครงสร้างภายในที่ไม่ใช่ public behavior
- ต้องมี regression test ยืนยันว่า income segment ยังคงสีเขียวเมื่อเป็น 100% และ expense segment ยังคงสีแดงเมื่อเป็น 100%

## Out of Scope

- การแก้ไขหรือนำข้อมูล mock เดิมกลับมา
- การ migrate Transaction เก่าที่ไม่มี `createdAt`
- การตั้งงบประมาณรายเดือนหรือการคำนวณ budget variance
- การรวม `saving` ในการ์ดกระแสเงินวันนี้
- การแสดงกราฟรายวันย้อนหลังหลายวัน
- การ export, search, server sync หรือ URL state สำหรับ Pagination
- การสร้าง chart library ภายนอกเพิ่มเติม

## Further Notes

- หากรายการยอดสูงสุดมีจำนวนมาก Pinned Tooltip ต้องเลื่อนดูได้โดยไม่ตัดข้อมูล
- Pagination จะมองเห็นเมื่อมีผลลัพธ์เกิน 10 รายการเท่านั้น จึงอาจไม่แสดงในข้อมูลเริ่มต้นที่ว่าง
- Issue tracker ยังไม่ได้ตั้งค่าในโปรเจกต์ จึงยัง publish spec พร้อม `ready-for-agent` ไม่ได้ ให้รัน `/setup-matt-pocock-skills` ก่อน publish
