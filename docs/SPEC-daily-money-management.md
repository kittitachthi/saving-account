# ระบบจัดการรายรับ–รายจ่ายประจำวัน

## Problem Statement

ผู้ใช้ต้องการวิธีบันทึกและติดตามการเงินส่วนตัวในแต่ละวันที่เรียบง่าย สามารถมองเห็นยอดคงเหลือ รายรับ รายจ่าย งบประมาณ และรายการล่าสุดได้จากหน้าจอเดียว โดยรายการที่บันทึกไว้ต้องไม่หายเมื่อรีเฟรชหรือกลับมาเปิดแอปอีกครั้ง

## Solution

สร้างแดชบอร์ดการเงินส่วนตัวแบบหน้าเดียวที่ให้ผู้ใช้ดูภาพรวมการเงิน กรองรายการ และเพิ่มรายรับหรือรายจ่ายผ่านแบบฟอร์มได้ทันที ระบบคำนวณยอดต่าง ๆ ใหม่จากรายการทั้งหมดโดยอัตโนมัติ และเก็บรายการไว้ในพื้นที่จัดเก็บภายในเบราว์เซอร์ของอุปกรณ์

หน้าจอต้องรองรับเดสก์ท็อป แท็บเล็ต และโทรศัพท์มือถือ โดยรักษาลำดับความสำคัญของยอดคงเหลือ การเพิ่มรายการ และรายการล่าสุดให้เข้าถึงง่าย

## User Stories

1. ในฐานะผู้ใช้ ฉันต้องการเห็นยอดคงเหลือทั้งหมด เพื่อให้รู้ว่ามีเงินพร้อมใช้งานเท่าไร
2. ในฐานะผู้ใช้ ฉันต้องการเห็นรายรับรวมของเดือนนี้ เพื่อให้เข้าใจเงินที่เข้ามาในเดือนปัจจุบัน
3. ในฐานะผู้ใช้ ฉันต้องการเห็นรายจ่ายรวมของเดือนนี้ เพื่อให้เข้าใจเงินที่ใช้ไปในเดือนปัจจุบัน
4. ในฐานะผู้ใช้ ฉันต้องการเห็นงบประมาณคงเหลือ เพื่อให้ควบคุมการใช้จ่ายไม่ให้เกินวงเงินที่ตั้งไว้
5. ในฐานะผู้ใช้ ฉันต้องการเห็นสัดส่วนงบประมาณที่ใช้ไป เพื่อให้ประเมินสถานะงบประมาณได้อย่างรวดเร็ว
6. ในฐานะผู้ใช้ ฉันต้องการเพิ่มรายการจากหน้าภาพรวม เพื่อให้บันทึกการเงินได้โดยไม่ต้องเปลี่ยนหน้า
7. ในฐานะผู้ใช้ ฉันต้องการกำหนดว่ารายการเป็นรายรับหรือรายจ่าย เพื่อให้ระบบคำนวณยอดคงเหลือได้ถูกต้อง
8. ในฐานะผู้ใช้ ฉันต้องการระบุชื่อรายการ เพื่อให้จำได้ว่าเงินแต่ละจำนวนมาจากหรือถูกใช้ไปกับอะไร
9. ในฐานะผู้ใช้ ฉันต้องการระบุจำนวนเงิน เพื่อให้ยอดรวมสะท้อนการเคลื่อนไหวของเงินจริง
10. ในฐานะผู้ใช้ ฉันต้องการเลือกหมวดหมู่ให้รายจ่าย เพื่อให้เข้าใจรูปแบบการใช้เงินของตนเอง
11. ในฐานะผู้ใช้ ฉันต้องการให้รายรับถูกจัดอยู่ในหมวดรายรับโดยอัตโนมัติ เพื่อไม่ต้องกรอกข้อมูลที่ซ้ำซ้อน
12. ในฐานะผู้ใช้ ฉันต้องการเห็นรายการใหม่ทันทีหลังบันทึก เพื่อให้มั่นใจว่าระบบรับข้อมูลแล้ว
13. ในฐานะผู้ใช้ ฉันต้องการให้ยอดคงเหลือ รายรับ รายจ่าย และงบประมาณปรับทันทีหลังบันทึก เพื่อให้ภาพรวมเป็นปัจจุบัน
14. ในฐานะผู้ใช้ ฉันต้องการเห็นรายการล่าสุดก่อน เพื่อให้ตรวจสอบกิจกรรมทางการเงินที่เพิ่งเกิดขึ้นได้ง่าย
15. ในฐานะผู้ใช้ ฉันต้องการเห็นวันที่ หมวดหมู่ และประเภทของแต่ละรายการ เพื่อให้แยกแยะรายการได้ชัดเจน
16. ในฐานะผู้ใช้ ฉันต้องการกรองเฉพาะรายรับ เพื่อให้ตรวจสอบแหล่งเงินเข้าได้ง่าย
17. ในฐานะผู้ใช้ ฉันต้องการกรองเฉพาะรายจ่าย เพื่อให้ตรวจสอบการใช้เงินได้ง่าย
18. ในฐานะผู้ใช้ ฉันต้องการกลับมาดูรายการทั้งหมดหลังกรอง เพื่อให้เห็นภาพรวมการเคลื่อนไหวของเงิน
19. ในฐานะผู้ใช้ ฉันต้องการเห็นรายรับและรายจ่ายด้วยสีหรือสัญลักษณ์ที่แตกต่างกัน เพื่อให้แยกประเภทได้ด้วยการมองอย่างรวดเร็ว
20. ในฐานะผู้ใช้ ฉันต้องการให้ระบบปฏิเสธชื่อรายการที่ว่าง เพื่อป้องกันรายการที่ไม่สามารถระบุความหมายได้
21. ในฐานะผู้ใช้ ฉันต้องการให้ระบบปฏิเสธจำนวนเงินที่เป็นศูนย์หรือติดลบ เพื่อป้องกันยอดรวมที่ไม่ถูกต้อง
22. ในฐานะผู้ใช้ ฉันต้องการปิดแบบฟอร์มโดยไม่บันทึกได้ เพื่อให้ยกเลิกการเพิ่มรายการได้อย่างปลอดภัย
23. ในฐานะผู้ใช้ ฉันต้องการให้รายการถูกเก็บไว้หลังรีเฟรชหน้า เพื่อไม่ต้องบันทึกข้อมูลเดิมซ้ำ
24. ในฐานะผู้ใช้ ฉันต้องการให้รายการถูกโหลดกลับมาเมื่อเปิดแอปอีกครั้งบนเบราว์เซอร์เดิม เพื่อให้ใช้งานต่อเนื่องได้
25. ในฐานะผู้ใช้ ฉันต้องการให้แอปยังเปิดใช้งานได้เมื่อข้อมูลที่บันทึกไว้เสียหาย เพื่อไม่ให้ข้อมูลผิดรูปแบบทำให้ทั้งหน้าจอพัง
26. ในฐานะผู้ใช้ใหม่ ฉันต้องการเห็นข้อมูลตัวอย่างเมื่อยังไม่เคยบันทึกข้อมูล เพื่อให้เข้าใจวิธีใช้งานและองค์ประกอบของหน้าจอ
27. ในฐานะผู้ใช้มือถือ ฉันต้องการใช้เมนูหลักบริเวณด้านล่างของหน้าจอ เพื่อให้เข้าถึงส่วนสำคัญด้วยนิ้วโป้งได้ง่าย
28. ในฐานะผู้ใช้มือถือ ฉันต้องการให้ข้อมูลและแบบฟอร์มพอดีกับหน้าจอ เพื่อให้ใช้งานได้โดยไม่ต้องเลื่อนในแนวนอน
29. ในฐานะผู้ใช้เดสก์ท็อป ฉันต้องการเห็นภาพรวมและรายการหลายส่วนพร้อมกัน เพื่อใช้พื้นที่หน้าจอได้อย่างมีประสิทธิภาพ
30. ในฐานะผู้ใช้ ฉันต้องการเห็นสัดส่วนรายจ่ายแยกตามหมวดหมู่ เพื่อให้ทราบว่ากำลังใช้เงินกับเรื่องใดมากที่สุด
31. ในฐานะผู้ใช้ ฉันต้องการลบรายการที่ไม่ต้องการ เพื่อให้ข้อมูลและยอดรวมสะท้อนรายการที่เหลือจริง
32. ในฐานะผู้ใช้ ฉันต้องการให้ยอดและสัดส่วนรายจ่ายปรับทันทีหลังลบ เพื่อให้ภาพรวมการเงินสอดคล้องกันทุกส่วน
33. ในฐานะผู้ใช้ ฉันต้องการให้แอปเริ่มด้วยธีมของระบบเมื่อยังไม่เคยเลือกเอง เพื่อให้หน้าจอสอดคล้องกับอุปกรณ์
34. ในฐานะผู้ใช้ ฉันต้องการเลือกธีมสว่างหรือมืดจากเมนูตั้งค่า เพื่อให้หน้าจอเหมาะกับสภาพแสง
35. ในฐานะผู้ใช้ ฉันต้องการให้แอปจำธีมล่าสุด เพื่อไม่ต้องตั้งค่าใหม่ทุกครั้ง
36. ในฐานะผู้ใช้ที่เปิดหลายแท็บ ฉันต้องการให้ทุกแท็บเปลี่ยนธีมตามทันที เพื่อให้ประสบการณ์สอดคล้องกัน
37. ในฐานะผู้ใช้คีย์บอร์ดหรือเทคโนโลยีช่วยการเข้าถึง ฉันต้องการให้ปุ่มธีมมี focus state, tooltip และชื่อการกระทำ เพื่อให้ใช้งานได้โดยไม่ต้องตีความไอคอน

## Implementation Decisions

- ใช้แอป React แบบหน้าเดียว โดยเก็บสถานะรายการและตัวกรองภายในส่วนประกอบระดับแอป
- โมเดล `Transaction` ประกอบด้วยรหัสรายการ ชื่อ หมวดหมู่ วันที่ จำนวนเงิน ประเภท และสัญลักษณ์
- ประเภทของรายการจำกัดเป็น `income` และ `expense`
- ยอดรายรับและรายจ่ายคำนวณจากรายการทั้งหมด ส่วนยอดคงเหลือเท่ากับรายรับรวมลบรายจ่ายรวม
- รายการใหม่ถูกเพิ่มไว้บนสุดเพื่อรักษาลำดับล่าสุดก่อน
- การลบ Transaction ใช้รหัสรายการ และคำนวณ Balance, Income, Expense, Budget และ Category breakdown ใหม่จากรายการที่เหลือ
- เมื่อรายการถูกลบ ระบบเขียนชุดรายการล่าสุดลง `localStorage` โดยอัตโนมัติ
- แบบฟอร์มเพิ่มรายการแสดงเป็น modal บนหน้าปัจจุบัน
- ฟิลด์หมวดหมู่แสดงเฉพาะรายจ่าย ส่วนรายรับใช้หมวดหมู่รายรับโดยอัตโนมัติ
- จำนวนเงินต้องมากกว่าศูนย์ และชื่อรายการต้องไม่เป็นข้อความว่างก่อนบันทึก
- ใช้ `localStorage` เป็นแหล่งจัดเก็บข้อมูลถาวรชั่วคราว โดยใช้ storage key ที่มีเวอร์ชันเพื่อรองรับการย้ายรูปแบบข้อมูลในอนาคต
- ระบบโหลดข้อมูลจาก `localStorage` เพียงครั้งเดียวเมื่อเริ่มต้น และบันทึกอัตโนมัติเมื่อรายการเปลี่ยนแปลง
- ข้อมูลที่โหลดต้องเป็นอาร์เรย์ และแต่ละรายการต้องมีรหัส ชื่อ จำนวนเงิน และประเภทที่ถูกต้อง รายการที่ไม่ผ่านการตรวจสอบจะถูกละทิ้ง
- หากไม่มีข้อมูล บันทึกเป็น JSON ไม่ถูกต้อง หรือข้อมูลระดับบนไม่ใช่อาร์เรย์ ระบบใช้ชุดข้อมูลตัวอย่าง
- การจัดเก็บเป็นแบบเฉพาะเบราว์เซอร์และอุปกรณ์ ไม่มีการส่งข้อมูลออกไปยังเซิร์ฟเวอร์
- ใช้การจัดวาง responsive: แถบด้านข้างบนเดสก์ท็อป แถบนำทางด้านล่างบนมือถือ และลดจำนวนคอลัมน์ตามความกว้างหน้าจอ
- ใช้คำศัพท์ Transaction, Income, Expense, Balance, Budget และ Category ให้สอดคล้องกับ glossary ของโครงการ
- Theme มีสองค่า `light` และ `dark`; Theme Preference ที่ถูกต้องมีลำดับความสำคัญเหนือ System Theme
- Settings Surface เป็น popover บนเดสก์ท็อปและ bottom sheet บนมือถือ โดยปิดได้จากพื้นที่ด้านนอกหรือปุ่ม Escape
- Theme Toggle แสดงธีมปลายทาง ใช้ animation สั้น เคารพ reduced motion และซิงก์ข้ามแท็บผ่าน storage event

## Testing Decisions

- ใช้การทดสอบระดับหน้าจอแอปเป็น testing seam หลักเพียงจุดเดียว โดยจำลองพฤติกรรมของผู้ใช้ผ่าน UI และตรวจผลลัพธ์ที่มองเห็นได้ รวมถึงผลลัพธ์ใน `localStorage`
- การทดสอบต้องเน้นพฤติกรรมภายนอก ไม่ตรวจ state ภายใน ชื่อฟังก์ชัน หรือโครงสร้างส่วนประกอบ
- ทดสอบการแสดงข้อมูลตัวอย่างเมื่อไม่มีค่าที่จัดเก็บไว้
- ทดสอบการโหลดรายการที่ถูกต้องจาก `localStorage` และการคำนวณยอดจากข้อมูลที่โหลด
- ทดสอบการสำรองกลับไปยังข้อมูลตัวอย่างเมื่อ JSON เสียหายหรือค่าที่โหลดไม่ใช่อาร์เรย์
- ทดสอบว่ารายการที่โครงสร้างไม่ถูกต้องถูกละทิ้งโดยไม่ทำให้หน้าจอพัง
- ทดสอบการเพิ่มรายรับผ่าน modal และตรวจว่ารายการ ยอดรายรับ และยอดคงเหลือเปลี่ยนอย่างถูกต้อง
- ทดสอบการเพิ่มรายจ่ายผ่าน modal และตรวจว่ารายการ ยอดรายจ่าย ยอดคงเหลือ และงบประมาณเปลี่ยนอย่างถูกต้อง
- ทดสอบว่าการเพิ่มรายการทำให้ข้อมูลล่าสุดถูกเขียนลง `localStorage`
- ทดสอบว่าชื่อว่าง จำนวนศูนย์ และจำนวนติดลบไม่สร้างรายการ
- ทดสอบตัวกรองทั้งหมด รายรับ และรายจ่ายจากเนื้อหาที่ผู้ใช้มองเห็น
- ทดสอบการลบรายการ โดยตรวจว่ารายการหายไป ยอดรวมปรับ และข้อมูลถูกนำออกจาก `localStorage`
- ทดสอบการปิด modal โดยปุ่มปิดและการคลิกพื้นที่ฉากหลังโดยไม่เพิ่มรายการ
- ทดสอบ viewport มือถืออย่างน้อยหนึ่งขนาด โดยตรวจว่าเมนูหลักอยู่ด้านล่างและไม่มี horizontal overflow
- ทดสอบการเลือกค่าเริ่มต้นจาก System Theme เมื่อไม่มี Theme Preference และเมื่อค่าที่จัดเก็บใช้ไม่ได้
- ทดสอบว่า Theme Preference ที่ถูกต้องถูกโหลด บันทึก และมีลำดับเหนือ System Theme
- ทดสอบการซิงก์ Theme ข้ามแท็บจาก storage event
- ทดสอบการเปิดและปิด Settings Surface รวมถึง Escape และการคลิกพื้นที่ด้านนอก
- ทดสอบ accessible name, tooltip, keyboard focus และ reduced-motion behavior ของ Theme Toggle
- ปัจจุบันโครงการยังไม่มีชุดทดสอบ UI ที่เป็น prior art จึงต้องเพิ่ม test runner และ browser-like environment ก่อนนำกรณีทดสอบเหล่านี้มาใช้

## Out of Scope

- บัญชีผู้ใช้ การเข้าสู่ระบบ และการซิงก์ข้อมูลข้ามอุปกรณ์
- ฐานข้อมูลหรือ API ฝั่งเซิร์ฟเวอร์
- การนำเข้าและส่งออกข้อมูล
- การแก้ไขรายการที่บันทึกแล้ว
- การตั้งค่างบประมาณโดยผู้ใช้
- การแยกข้อมูลตามเดือนจริงและการเลือกช่วงวันที่
- รายการประจำหรือการบันทึกอัตโนมัติ
- การเชื่อมต่อบัญชีธนาคาร
- การแจ้งเตือนเมื่อใกล้เกินงบประมาณ
- การเข้ารหัสข้อมูลภายใน `localStorage`
- การรองรับผู้ใช้หลายคนในเบราว์เซอร์เดียวกัน
- การเผยแพร่สเปกเข้าสู่ issue tracker จนกว่าโครงการจะตั้งค่า issue tracker และ triage labels

## Further Notes

- ค่าเดือน เปอร์เซ็นต์เปรียบเทียบ งบประมาณ และสัดส่วนหมวดหมู่ในหน้าต้นแบบยังเป็นค่าตัวอย่าง ไม่ได้คำนวณจากช่วงวันที่หรือหมวดหมู่จริงทั้งหมด
- `localStorage` เหมาะกับต้นแบบและการใช้งานส่วนตัวบนอุปกรณ์เดียว แต่ไม่ควรถือเป็นระบบสำรองข้อมูล
- ก่อนขยายโมเดลข้อมูล ควรกำหนดรูปแบบวันที่เป็นค่าที่เครื่องอ่านได้ เช่น ISO 8601 และค่อยแปลงเป็นรูปแบบภาษาไทยตอนแสดงผล
- สเปกนี้เคารพการตัดสินใจใน ADR-001 ที่กำหนดให้แดชบอร์ดหน้าเดียวและการเพิ่มรายการแบบ modal เป็นแนวทางหลัก
