# ADR-009: แสดงกระแสเงินวันนี้และแบ่งหน้ารายการธุรกรรม

## สถานะ

ยอมรับ

## บริบท

การ์ด “งบประมาณคงเหลือ” ใช้งบประมาณตัวอย่างที่ผู้ใช้ยังตั้งค่าไม่ได้ จึงไม่ให้ข้อมูลที่เชื่อถือได้ ขณะเดียวกันรายการธุรกรรมกำลังมีจำนวนมากขึ้น และข้อมูลเดิมใช้ข้อความอย่าง `วันนี้` เป็นวันที่ ทำให้ไม่สามารถคำนวณวันตามเวลาจริงหรือเปลี่ยนวันอัตโนมัติได้

## การตัดสินใจ

### การ์ดรายรับเทียบรายจ่ายวันนี้

- แทนที่การ์ด “งบประมาณคงเหลือ” ด้วย “รายรับเทียบรายจ่ายวันนี้”
- ใช้เฉพาะรายการ `income` และ `expense` ที่เกิดในวันปฏิทินท้องถิ่นปัจจุบัน ไม่รวม `saving`
- แสดงยอดรายรับและรายจ่ายที่อ่านได้โดยไม่ต้องเปิด Tooltip
- แสดงแถบแนวนอนสีเขียวสำหรับรายรับและสีแดงสำหรับรายจ่าย
- สีของแต่ละฝั่งผูกกับประเภทโดยตรงเสมอ: `income` ต้องเป็นสีเขียวและ `expense` ต้องเป็นสีแดง แม้มีเพียงฝั่งเดียวจนกินพื้นที่ 100% ของแถบ
- สัดส่วนของแต่ละฝั่งเท่ากับยอดของฝั่งนั้นหารด้วยผลรวมรายรับและรายจ่ายวันนี้ ทั้งสองฝั่งรวมกันเป็น 100%
- เมื่อทั้งสองยอดเป็นศูนย์ แสดงแถบว่างและข้อความ `ยังไม่มีรายการวันนี้`
- เมื่อมีเพียงฝั่งเดียว ฝั่งนั้นแสดง 100% และอีกฝั่งแสดง 0%
- Tooltip แสดงประเภท ยอดรวม สัดส่วน จำนวนรายการ และรายการมูลค่าสูงสุด หากไม่มีรายการให้แสดงสถานะว่าไม่มีรายการ
- หากมีหลายรายการที่มูลค่าเท่ากับค่าสูงสุด ให้แสดงทุกรายการโดยเรียงใหม่สุดก่อน พร้อมชื่อ ยอดเงิน และเวลา ห้ามเลือกรายการหนึ่งแล้วละทิ้งรายการอื่น
- Hover Tooltip ยังคงไม่รับ pointer events และจำกัดความสูงตาม viewport หากเนื้อหาล้นให้แจ้ง `คลิกเพื่อตรึงและดูทั้งหมด`
- Pinned Tooltip รับ pointer events และเลื่อนดูรายการมูลค่าสูงสุดทั้งหมดได้ การ interact ภายใน Tooltip ไม่ถือเป็น outside dismissal
- ทั้งแถบและข้อความสรุปของแต่ละฝั่งเป็น trigger เพื่อให้ฝั่ง 0% ยังเข้าถึง Tooltip ได้
- Interaction ใช้ Canonical Chart Interaction: hover ตาม pointer, click/tap เพื่อ pin, คลิกซ้ำหรือ Escape หรือคลิกภายนอกเพื่อปิด และคลิกอีกฝั่งเพื่อสลับข้อมูล

### เวลาและข้อมูลเดิม

- Transaction รูปแบบใหม่เก็บ `createdAt` เป็นเวลาจริง และใช้เป็น source of truth ของวันที่
- คำว่า “วันนี้” อ้างอิงวันปฏิทินตาม timezone ท้องถิ่นของ browser
- เมื่อเปิดแอปข้ามเที่ยงคืน ข้อมูลรายวันและป้ายวันที่ต้องเปลี่ยนอัตโนมัติโดยไม่ต้อง refresh
- ป้ายวันที่คำนวณจาก `createdAt`: วันปัจจุบันเป็น `วันนี้`, หนึ่งวันก่อนเป็น `เมื่อวาน`, และวันที่เก่ากว่านั้นแสดงวันที่ภาษาไทย
- ล้างข้อมูล mock และ storage schema เดิมแบบ one-time reset แล้วเริ่มด้วยรายการว่าง ไม่ทำ migration รายการเก่าที่ไม่มี `createdAt`

### Pagination ของรายการธุรกรรม

- แบ่งหน้าหลังใช้ตัวกรองประเภทแล้ว หน้าละ 10 รายการ
- เรียงรายการใหม่สุดก่อน และใช้ลำดับรองที่แน่นอนเมื่อเวลาเท่ากัน
- ใช้เลขหน้า พร้อมปุ่มก่อนหน้าและถัดไป
- ซ่อน Pagination เมื่อผลลัพธ์มีไม่เกิน 10 รายการ
- แสดง `ยังไม่มีรายการธุรกรรม` เมื่อไม่มีรายการ
- กลับหน้า 1 เมื่อเปลี่ยนตัวกรองหรือเพิ่มรายการ
- เมื่อลบรายการจนหน้าปัจจุบันว่าง ให้เลื่อนไปหน้าสุดท้ายที่ยังมีข้อมูล
- Undo คงหน้าปัจจุบันไว้เมื่อหน้านั้นยังถูกต้อง

## แบบจำลองโดเมน

- **Transaction** เป็น source of truth และมี `createdAt`
- **Daily Cashflow Summary** เป็น derived data จาก Transaction ของวันท้องถิ่นปัจจุบัน แยก `income` และ `expense`
- **Cashflow Segment** แทนฝั่งรายรับหรือรายจ่าย พร้อมยอดรวม เปอร์เซ็นต์ จำนวนรายการ และชุดรายการที่มีมูลค่าสูงสุดร่วมกัน
- **Filtered Transactions** เป็นรายการหลังเลือกประเภทและก่อนแบ่งหน้า
- **Transaction Page** เป็น slice ขนาดสูงสุด 10 รายการ พร้อมเลขหน้าปัจจุบันและจำนวนหน้าทั้งหมด

## ผลกระทบ

- การ์ดสรุปแสดงข้อมูลที่มาจากรายการจริงแทนค่าตัวอย่าง
- จำเป็นต้องมี clock/day-boundary lifecycle เพื่อคำนวณวันใหม่ขณะเปิดแอปค้างไว้
- Storage schema เปลี่ยนแบบไม่รองรับข้อมูลเก่า ซึ่งยอมรับได้เพราะข้อมูลปัจจุบันเป็น mock
- Shared interaction ควรถูกทำให้ใช้ซ้ำได้กับแถบแนวนอน ไม่ผูกกับ geometry ของ Donut เท่านั้น
